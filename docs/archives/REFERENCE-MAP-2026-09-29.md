# QPOS — carte de référence des parcours

**État observé : 29/09/2026.** Cette carte sert de registre avant les passes verticales S4/S5. Elle recense les fichiers principaux, règles visibles, permissions, risques et critères à vérifier. Elle ne remplace pas les décisions métier ni la recette de chaque passe.

## État et règles de propriété

- Branche main, arbre de travail propre au relevé ; main est en avance d’un commit sur origin/main : f4beb19 (wip: sprint 3 + roadmap unifiee).
- Référence courte : docs/ROADMAP-UNIFIEE.md ; ancienne roadmap : docs/archives/modernization-roadmap.md.
- Laravel 10.48.22 ; PHP CLI XAMPP 8.2.12. La version PHP d’Apache reste à comparer à la CLI.
- Cartographie actuelle : 134 routes, 108 protégées par permission et 26 exceptions documentées dans docs/routes-permissions.md.
- Avant édition, chaque fichier reçoit une passe propriétaire. Les autres passes consignent leurs besoins sans le modifier.
- Fichiers transverses à réserver à une passe globale unique après collecte des besoins : routes/web.php, lang/fr.json, lang/en.json, layout/shell/jetons CSS communs et configuration Vite/build.
- Product.php et les invariants de quantité/stock appartiennent à la passe 1. La passe 5 consomme ce contrat pour achats/imports.
- OrderController et le cycle de vente complet (checkout, historique, règlements, factures) appartiennent à la passe 1. La passe 5 traite le cycle d’achat/import ; les rapports de vente sont à la passe 6.
- Les commits par nature et l’édition unique d’un fichier peuvent entrer en conflit lorsqu’un contrôleur exige des changements de sécurité et de performance. Proposition : commits distincts pour des fichiers distincts ; un fichier à responsabilités mixtes reste dans un commit de sa passe propriétaire. À valider avant le premier changement de code.

## Artefacts transverses : une seule intervention

- routes/web.php et App\Support\PermissionRoutes : regrouper les besoins de routes/permissions dans la passe globale sécurité, après les neuf inventaires.
- lang/fr.json, lang/en.json et messages de validation : collecter les clés durant les passes, modifier les catalogues une seule fois.
- resources/css/app.css, jetons, layouts, theme.js/shell.js et vite.config.js : changements de socle UI/build dans une passe globale UX/performance ; les vues restent dans leur passe propriétaire.
- composer.json, composer.lock et Dockerfiles : aucun changement dans les passes verticales ; propriété du lot final runtime/framework.
- config/cors.php, cookies/sessions, échappement global et réglages sensibles : audit de sécurité global ; config/system.php demeure propriétaire de la passe 8.
- Hors scope déjà recensé : trois méthodes mortes avec abort_if, ProductController::show sans permission, 106 icônes Font Awesome, retrait des layouts DataTables legacy. Signaler, ne pas corriger sans validation du périmètre.

## Règle de clôture d’une passe

Avant édition : confirmer propriétaire et critères. Après édition : consigner fichiers touchés, critères vérifiés, décisions en attente et risques reportés. Pas de commit automatique. Aucun réaudit complet des autres parcours.
